# Implementation Plan: EngageBlog

## Summary
A blog posting app for content teams providing advanced analytics and seamless video integration. It includes features for content publishing, media management, analytics dashboards, and admin control panels.

## PRD gaps compensated
None — PRD sections are aligned.

## Blueprint inventory
A blueprint YAML has been written for each of these models. Develop stage will run `bundle exec rails rhino:blueprint` to materialize them.

- `server/.rhino/blueprints/_roles.yaml` — roles: admin, content_team_member
- `server/.rhino/blueprints/posts.yaml` — Post
- `server/.rhino/blueprints/videos.yaml` — Video
- `server/.rhino/blueprints/analytics_data.yaml` — AnalyticsData

## Models (reference)
### Post
- Ownership: organization-scoped
- Key fields: title, content, status, published_at
- Relationships: belongsTo Organization, belongsTo User, hasMany Video, hasMany AnalyticsData

### Video
- Ownership: organization-scoped
- Key fields: title, url, duration
- Relationships: belongsTo Organization, belongsTo User, belongsTo Post

### AnalyticsData
- Ownership: organization-scoped
- Key fields: event_type, event_data, recorded_at
- Relationships: belongsTo Organization, belongsTo Post

## Extras (NOT covered by blueprint — develop stage implements these by hand)
- **Model + action**: `User` migration
- **Rule**: Add `first_name`, `last_name`, `approved`, `profile_completed` columns to the `users` table via migration.
- **Where the code lives**: `db/migrate/...`
- **Acceptance criterion**: AC-60

- **Model + action**: Seed generation
- **Rule**: Create roles and assigning users via UsersRole to allow login and route access.
- **Where the code lives**: `db/seeds.rb`
- **Acceptance criterion**: AC-61

- **Model + action**: Dashboard Analytics Endpoint
- **Rule**: Serve aggregated stats (`Total Content Reach`, `Video Watch Hours`, `Avg. Read Completion`) for the Dashboard landing page.
- **Where the code lives**: `app/controllers/api/dashboard_controller.rb`
- **Acceptance criterion**: AC-59

## Implementation order (recommended stage flow)

1. **Plan** — this artifact set (YAMLs, plan, criteria, index).
2. **Develop** — phase A: `bundle exec rails rhino:blueprint` + migrations. Phase B: implement **Extras**. Phase D: write backend unit + integration tests for every AC.
3. **UI / UI-Integration** — build screens listed above.
4. **Test** — run `bundle exec rails test` to confirm green and tighten anything broken.
5. **Review** — PRD compliance + test/coverage report.
